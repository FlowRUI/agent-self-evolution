# Grep-First Memory Evidence Retrieval

> 在生成可复用知识之前，先从长程 Agent 历史中检索可追溯证据的隐私友好方法。

本文是独立重写、无实现代码的设计说明，示例均为虚构内容，不复刻任何雇主代码、Prompt、日志、目录、服务名、Schema 或运行参数。

## 核心问题

长会话产生的历史远超模型上下文容量。记忆系统需要分别解决：相关证据在哪里，以及这些证据是否足以支撑一条可复用规则。

将全部历史交给模型既昂贵又扩大隐私暴露面；只依赖摘要则可能丢失支撑结论的原始观察。

## 方法

先用确定性的文本检索缩小范围，再让语义推理仅处理少量、带引用的证据窗口：

1. 建立只包含记录 ID、时间、工具类别、结果标签和脱敏关键词的轻量索引。
2. 使用精确关键词、错误类别和事件标签进行第一阶段检索。
3. 围绕命中项加载有限上下文，并保留稳定证据 ID。
4. 区分失败表象与根因，记录条件、可观察失败、诊断动作和不确定性。
5. 搜索已有知识，排除重复、冲突或适用边界不同的规则。
6. 将候选规则送入审查队列，不允许静默修改可复用 Skill。

## 为什么先使用 grep 类检索

- 结果可复现、容易审查。
- 大部分无关历史不会进入模型上下文。
- 可以只检索脱敏索引，降低隐私风险。
- 每个候选项都能回溯到证据 ID。
- 后续仍可叠加语义检索，不会互相排斥。

## 拒绝条件

遇到下列情况应拒绝沉淀：

- 只有一次且含义不明确的案例；
- 依赖私有业务名词、字段、阈值或迁移背景；
- 已被现有知识覆盖；
- 结论强度超过证据；
- 离开原始私有上下文便无法安全复用。

## 公开前隐私门禁

删除凭据、Token、Cookie、域名、账号、邮箱和真实路径；将用户、会话、项目、表、指标及故障替换为虚构示例；不公开完整 Prompt、模型输出、截图、堆栈和工具载荷；最后进行确定性密钥扫描并要求人工批准。

## 局限性

纯文本检索无法理解改写后的语义。更成熟的系统可以组合词法检索、元数据过滤和语义检索，但证据引用与隐私门禁应始终保持为确定性约束。
